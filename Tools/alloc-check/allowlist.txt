# Paths from inside a protected region to the heap, or to a call through a register, that Duet3Expansion may keep, see
# README.md. alloc-check.py fails for every other one. One key per line, then a comment:
#   Function [kind] -> target           kind: suspended, critical, basepri, primask or isr; target: the allocation function
#                                       first reached (operator new, Tasks::AllocPermanent, ...), the heap function, or
#                                       "indirect call"
#   path/below/src.cpp: Function [...]  static functions and functions in anonymous namespaces
#
# The list is the state of 3.7-dev at 9402264a (RRFLibraries 3.7-dev 888b479, CoreN2G 3.7-dev 7d41892) in TOOL1LC, EXP1HCL and
# SZP; the census in census.md was made at 9ac5016c. Each comment gives the verdict of the census and the reason:
#   SUSPECT          the heap is reached with the scheduler suspended or interrupts masked; the fix branch is in brackets. An
#                    entry stays SUSPECT until its fix is merged, then the key goes away
#   SAFE-PRIMED      the allocation inside the region is always served by a free list that is filled before the region
#   SAFE-NO-HEAP     a call through a register: every target the firmware sets was read and none reaches the heap
#   SAFE-NO-TARGET   a call through a register whose pointer the firmware never sets, so it never runs
#   SAFE-RETURN      the jump through a register is an exception return to a task, not a call
# A new entry needs the reason why the heap is not reached there. Better: allocate before the region and free after it.
# "make update" rewrites the list from the firmware and keeps the comments of the entries that stay.
